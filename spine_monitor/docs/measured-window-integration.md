# Remaining work: live measured windows

The measured-limit extractor accepts a request whose raw chunks span exactly five seconds. The backend currently requests features once after a session ends and stores one feature set per session. It does not submit or persist a series of five-second windows, and therefore does not provide a live measured-limit assessment. Existing whole-session features must not be presented as those windows.

Completing the path requires an ingestion-driven scheduler with per-session, per-boot window watermarks, bounded waiting for late streams, sample-accurate slicing and explicit incomplete windows when samples, clock anchors or calibrations are absent. It must be restart-safe and deduplicate replayed MQTT messages. Persist each window independently with a unique session/boot/window key and keep the existing session feature set separately. Assess at each window end using data available at that instant; do not backdate a live alert after end-of-session processing. Tests must cover gaps, late and out-of-order data, multiple boots, clock uncertainty, restart, stale windows and simultaneous sessions.

The current gateway does not acquire IMU calibration. A gyro alone cannot establish absolute orientation: an independently measured reference, its timestamp, mounting and bias must be captured and transported. Integration from that reference must account for gaps and drift. Until then the IMU result remains incomplete. Stretch references are usable for the measured limit only when the operator explicitly attests the straight-back posture. Reference-effort EMG requires an explicitly marked interval and a personal amplitude reference; ordinary repetitions and resting EMG do not establish it.
