# Remaining work: live measured windows

The extractor evaluates the latest five seconds from a request containing at least that span. A measured feature carries its own five-second window; the enclosing feature set retains the full session span. The backend currently requests features once after a session ends and stores one feature set per session. It does not submit or persist a series of five-second windows, and therefore does not provide a live measured-limit assessment.

Completing the live path requires an ingestion-driven scheduler with per-session, per-boot window watermarks, bounded waiting for late streams, sample-accurate slicing and explicit incomplete windows when samples, clock anchors or calibrations are absent. It must be restart-safe and deduplicate replayed MQTT messages. The store provides independent, deduplicated session/boot/window records, separate from session feature sets, but the scheduler does not yet write them. Assess at each window end using data available at that instant; do not backdate a live alert after end-of-session processing. Tests must cover gaps, late and out-of-order data, multiple boots, clock uncertainty, restart, stale windows and simultaneous sessions.

The current gateway does not acquire IMU calibration. A gyro alone cannot establish absolute orientation: an independently measured reference, its timestamp, mounting and bias must be captured and transported. The engine can integrate from a supplied reference through contiguous, uniformly sampled gyro data, and rejects gaps; drift remains a limitation. Until the reference is captured, the IMU result remains incomplete. Stretch references are usable for the measured limit only when the operator explicitly attests the straight-back posture. Reference-effort EMG requires an explicitly marked interval and a personal amplitude reference; ordinary repetitions and resting EMG do not establish it.
